## 1. 目标

**M4.1**：自研雪花算法——41 bit 毫秒时间戳（纪元 2026-01-01，可用 69 年）+ 10 bit 机器位（dataCenter 5 + work 5）
+ 12 bit 序列（同毫秒 4096）；时钟回拨的分档处置。**M4.2**：机器位不再配置文件写死，Redis Lua
INCR 取号 + 取模轮转分配，多实例各自领号。

## 2. 设计取舍

- **时钟回拨分档（本迭代核心）**：回拨 ≤5ms 自旋等待追平（NTP 微调是常态，等待优于报错）；
  >5ms 抛异常拒绝发号——**宁可短暂不可用，绝不冒重复 ID 风险**（ID 进了唯一索引和分片路由，重复是灾难）
- **时间源构造器注入（默认系统时钟）**：回拨行为可测——受控时钟复现 3ms 等待/100ms 拒绝，
  不真改系统时间。测试里发现真坑：固定时钟 + 序列耗尽 = tilNextMillis 永久自旋（时间必须前进是雪花前提）
- **轮转分配而非抢占式租约（与生产方案差距的主动声明）**：INCR 取模轮转不保证独占——实例数 >32
  或重启时序窗口内同 workId 双实例可能；占用登记（Hash value=pid@host）只做观测排障不做强校验。
  生产演进：租约+心跳续期+冲突重试（ZooKeeper/Redisson 锁语义）。教学取舍：轮转一行 Lua 讲清
  "机器位从哪来"的问题本质，任务卡声明局限
- **装配策略**：配置固定 workId > Redis 分配 > 兜底 0（分配器故障回退固定值+error 告警——
  启动失败优于静默不可用，人工介入）。@AutoConfigureAfter(RedisAutoConfiguration) 保证
  @ConditionalOnBean(StringRedisTemplate) 评估时序正确（starter 条件装配的经典坑，M3.14 同款）
- **业务切换点暂不替换**：现有 IdWorker（MyBatis-Plus）继续服务存量链路；M4.4 分片接入时
  订单域统一切自研生成器（切换一次到位，避免双生成器并存的时间戳纪元差异）

## 5. 学习清单

**核心知识点**
1. **雪花位账**：41+5+5+12=63（正 long）；每段语义与容量——时间戳定寿命（69 年）、机器位定规模（1024 实例）、序列定单机峰值（4096/ms ≈ 400 万/s）
2. **时钟回拨是雪花的命门**：ID 单调性依赖时间不倒流；分档处置（等待/拒绝）是工程答案，"拒绝生成"本身就是一种保护
3. **可测性设计**：时间源注入让"时间"从环境变量变成依赖参数——不可测的系统时间是回拨逻辑测试的最大障碍
4. **机器位分配的三个层次**：配置写死（单机）→ 中间件轮转（教学）→ 租约心跳（生产）；轮转的问题不在分配而在"回收"
5. **starter 条件装配时序**：@ConditionalOnBean 只看"此刻已注册的 bean 定义"，@AutoConfigureAfter 是给条件排队

**面试必问题**
1. "雪花算法讲一下"——位账+每段容量+为什么趋势递增（时间在高位）；追问单机峰值→4096/ms
2. "时钟回拨怎么办？"——分档：小回拨等待（NTP 常态）、大回拨拒绝发号（重复 ID 是唯一索引/分片路由的灾难）；能讲测试时发现的"固定时钟死循环"更佳
3. "workId 怎么分配的？"——三层次演进；讲清轮转的局限（不独占）与生产方案（租约心跳）
4. "为什么自己写而不用 IdWorker？"——时钟回拨策略可控可测、机器位分配策略可插拔、位账自己讲得清

## 1. 目标

产出 Localink 的产品需求文档（`docs/prd.md`），明确业务边界、功能清单、非功能指标与里程碑映射，作为后续所有设计与迭代的依据。同时落地项目规则文件（`AGENTS.md`）与进度跟踪文件（`docs/roadmap.md`）。

## 2. 设计取舍

- **为什么先写 PRD 再写代码**：企业开发中"需求冻结 → 架构设计 → 迭代开发"是标准流程；PRD 中的功能编号（F-XXX-XX）会在后续任务卡、提交信息中被引用，保证可追溯
- **为什么明确"不做什么"（第 6 节）**：边界不清是项目烂尾的首因；砍掉支付/推荐算法等才能把精力集中在面试考察的高并发与一致性上
- **为什么非功能指标留"以 M7 实测为准"**：简历数据必须真实可复现，先定目标值，最终以本机压测数据修正
- **优先级划分逻辑**：P0 = 业务闭环最小集；P1 = 面试考察的高并发/一致性能力；P2 = 差异化运营与社区亮点

## 5. 学习清单

**核心知识点**
1. PRD 的标准结构：背景 → 用户/场景 → 业务域 → 功能清单 → 非功能需求 → 边界 → 验收
2. 业务域划分方法：按"数据归属与变更频率"切域（账户/商户/优惠/交易/社区/运营/基础设施）
3. 非功能需求的写法：必须可度量（QPS、RT、一致性收敛方式），拒绝"高性能、高可用"式空话

**面试必问题**
1. "介绍一下你的项目"——用 PRD 第 1、3、4 节即可组织 1 分钟版本回答
2. "你的项目有什么亮点？"——对应 F-TRD 全组（一致性闭环）+ F-COM-04/05（ES 与热榜）
3. "为什么做社区扩展？"——业务闭环叙事：商户引流 → 优惠转化 → UGC 沉淀 → 社区反哺商户曝光

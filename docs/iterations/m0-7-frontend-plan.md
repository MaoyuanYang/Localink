## 2. 设计取舍

- **为什么加前端（修改 PRD "不做 UI" 边界）**：后端作品需要演示载体——面试时"打开页面点一次秒杀"比"看 Apifox 截图"有说服力；边界改为"UI 仅作演示，不做生产级视觉设计，接口权威验证仍是 Apifox"
- **为什么选 React+TS 而不是跟随参考项目的 Vue3**：① 铁律要求重写实现，不同技术栈天然杜绝复制粘贴嫌疑；② TypeScript 类型对齐后端 DTO，联调成本低；③ AntD 让 /admin 后台零设计成本。代价：无法复用 hmdp-vue3 任何代码，全部手写
- **为什么单工程双区而非两个工程**：双工程 = 两套构建 + 两份 axios 封装 + 类型重复维护，演示项目没有这笔预算；路由前缀 `/admin` 分区即可共享基建
- **为什么 Zustand 而非 Redux Toolkit**：全局状态只有登录态/用户信息等少数几个，RTK 的样板代码没有对应收益；Zustand ~1KB 无模板
- **为什么等 M1 完成再写代码**：现在后端只有 `/ping`，前端只能写 mock——维护 mock 是纯浪费且会产生"假进度"；M1 交付登录/商户/券 API 后，W0 每个页面都能对接真实接口
- **为什么前端线挂接后端里程碑而非独立排期**：前端是后端的演示层，超前开发必然返工；W0~W4 分别以前置 M1/M3/M5/M6/M7 为门禁，"不超前开发、不维护 mock"写入规范
- **为什么仓内顶层目录而非独立仓库**：单仓管理，PR 与文档同步演进；`localink-web/` 非 Maven 模块，不进 `mvnw package`，构建链路互不干扰

## 5. 学习清单

**核心知识点**
1. 前后端分离协作契约：统一返回体解包、token 头注入、错误码分段、分页参数——前端拦截器设计完全由后端规范反推
2. Monorepo 的轻量做法：顶层目录 + 独立构建链 vs 独立仓库的取舍（协作成本 vs 隔离性）
3. 演示型前端的范围控制：以"后端里程碑就绪 API"为门禁，避免 mock 维护与超前返工

**面试必问题**
1. "你的项目有前端吗？"——有，React+TS 演示界面，单工程双区（C 端 + /admin 后台），定位是后端能力的演示载体
2. "为什么不用参考项目的 Vue 前端？"——铁律要求重写实现；且 TS 类型对齐后端 DTO，AntD 降低后台成本
3. "前后端怎么联调的？"——Vite dev proxy 到 8086，axios 拦截器统一 token 注入与 Result 解包，错误码 toast 兜底

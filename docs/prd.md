## 1. 项目背景与定位

Localink 是一个**本地生活社区平台**，融合两大业务板块：

1. **商户与优惠板块**：商户浏览、优惠券发放与高并发秒杀抢购（工程能力主战场）
2. **UGC 社区板块**：用户探店分享、关注关系、Feed 流、搜索与热榜（业务差异化主战场）

对标业务形态：大众点评（商户+评价）+ 美团限时秒杀 + 小红书社区。

## 2. 目标用户与核心场景

| 角色 | 核心场景 |
|---|---|
| 普通用户 | 浏览商户 → 抢购秒杀券 → 到店核销；发探店帖、点赞评论、关注达人 |
| 达人/KOL | 发布优质探店内容，积累粉丝，内容进入热榜获得更多曝光 |
| 运营人员 | 发放优惠券、设置秒杀活动、圈选人群做开抢预通知、查看店铺 Top 买家 |

## 3. 业务域划分

| 域 | 包含内容 |
|---|---|
| 账户域 | 验证码登录、会话管理、用户资料、会员等级、签到 |
| 商户域 | 商户类型、商户信息、附近商户（GEO） |
| 优惠域 | 普通券、秒杀券（库存/时间窗/人群限制）、订阅提醒 |
| 交易域 | 秒杀下单、订单、取消回流、对账补偿 |
| 社区域 | 帖子、评论、点赞、关注、Feed 流、搜索、热榜、内容审核 |
| 运营域 | 开抢预通知、每日 Top 买家、订阅自动发券 |
| 基础设施工 | 缓存体系、分布式锁、幂等、限流、MQ、延迟队列、全局 ID、分库分表 |

## 4. 功能需求清单

优先级：P0 核心闭环 / P1 高并发保障 / P2 差异化亮点

### 4.1 账户域
| 编号 | 需求 | 优先级 |
|---|---|---|
| F-ACC-01 | 手机号+验证码登录（模拟短信，验证码写日志） | P0 |
| F-ACC-02 | 分布式会话（Redis 共享 Session，双拦截器鉴权） | P0 |
| F-ACC-03 | 用户资料查询与修改、会员等级（0~9） | P0 |
| F-ACC-04 | BitMap 用户签到与连续签到统计 | P2 |
| F-ACC-05 | HyperLogLog UV 统计（商户/帖子浏览去重计数） | P2 |

### 4.2 商户域
| 编号 | 需求 | 优先级 |
|---|---|---|
| F-SHOP-01 | 商户类型列表、商户 CRUD | P0 |
| F-SHOP-02 | 商户详情多级缓存查询（本地缓存+Redis+布隆+空值+DCL 重建） | P1 |
| F-SHOP-03 | 按类型分页查询、GEO 附近商户 | P2 |

### 4.3 优惠域
| 编号 | 需求 | 优先级 |
|---|---|---|
| F-VOC-01 | 普通券/秒杀券 CRUD（库存、时间窗、会员等级限制） | P0 |
| F-VOC-02 | 秒杀券详情多级缓存查询 + 失效广播 | P1 |
| F-VOC-03 | 库存预热到 Redis、加库存同步 | P1 |
| F-VOC-04 | 到券提醒订阅/取消/状态查询 | P2 |

### 4.4 交易域（项目核心）
| 编号 | 需求 | 优先级 |
|---|---|---|
| F-TRD-01 | 秒杀前置令牌（一次性，防接口刷） | P1 |
| F-TRD-02 | 入口限流（令牌桶/滑动窗口，IP+用户双维度） | P1 |
| F-TRD-03 | Lua 原子扣减（库存+一人一单+对账流水，hash tag 同槽位） | P1 |
| F-TRD-04 | Kafka 异步建单（消费幂等、延迟消息丢弃） | P1 |
| F-TRD-05 | 失败回滚（DEL 库存 key 回源 DB，指数退避重试，终失败落表+告警） | P1 |
| F-TRD-06 | 三层对账（Redis 流水 ↔ 对账日志 ↔ 订单状态）+ 差异补偿 | P1 |
| F-TRD-07 | 取消订单：库存回流 + 自动发券给最早订阅者 | P2 |
| F-TRD-08 | 分库分表：订单按用户分库、按券分表，路由表反查 | P1 |
| F-TRD-09 | 订单超时自动关闭：延迟队列超时扫描 → 系统取消 → 库存回流 | P1 |

### 4.5 社区域（差异化）
| 编号 | 需求 | 优先级 |
|---|---|---|
| F-COM-01 | 发帖/删帖/详情/分页、评论、点赞与点赞榜 | P0 |
| F-COM-02 | 关注/取关/共同关注 | P0 |
| F-COM-03 | Feed 流：推模式 + 滚动分页 → 推挽结合 | P1 |
| F-COM-04 | ES 全文搜索（帖子/商户，高亮+聚合筛选），Kafka 同步 | P1 |
| F-COM-05 | 热榜（点赞/评论/浏览加权 + 时间衰减 + 定时快照） | P2 |
| F-COM-06 | 内容审核：DFA 敏感词 + MQ 异步审核状态机 | P2 |
| F-COM-07 | 图片上传：本地存储、存储接口可插拔（发帖前置） | P0 |

### 4.6 运营域
| 编号 | 需求 | 优先级 |
|---|---|---|
| F-OPE-01 | 开抢前 2 分钟预通知（延迟队列 + 人群圈选） | P2 |
| F-OPE-02 | 店铺每日 Top 买家（ZSet 统计） | P2 |
| F-OPE-03 | 库存回流自动发券并通知 | P2 |

## 5. 非功能需求

| 类别 | 指标 |
|---|---|
| 性能 | 秒杀接口支撑突发流量，单机压测目标 QPS ≥ 2000（以 M7 实测为准），P99 RT < 500ms |
| 一致性 | 不超卖、不少卖；Redis/Kafka/DB 之间最终一致，对账任务可发现可补偿 |
| 可用性 | 入口限流防雪崩；缓存多层防护防穿透/击穿/雪崩；MQ 消费幂等防重复 |
| 扩展性 | 热点表分库分表；全局 ID 跨分片唯一；组件全部框架化可复用 |
| 可观测 | 关键链路埋点指标（回滚次数、限流触发、对账差异）暴露到 /actuator |

## 6. 业务边界（明确不做）

- 真实支付/核销（订单状态机到"已创建/已取消"为止）
- 真实短信/推送通道（以日志 + 去重窗口模拟，接口可插拔）
- 推荐算法（Feed 仅时间序，不做个性化推荐）
- 管理后台 UI（纯后端 API，Apifox 验证）

## 7. 里程碑映射

| 里程碑 | 内容 | 对应需求 |
|---|---|---|
| M0 | 工程奠基 | — |
| M1 | 基础业务闭环 | F-ACC-01~03、F-SHOP-01、F-VOC-01 |
| M2 | 缓存体系 | F-SHOP-02、F-VOC-02 |
| M3 | 秒杀核心链路 | F-TRD-01~06 |
| M4 | 数据层扩展 | F-TRD-08 |
| M5 | 一致性与运营 | F-TRD-07、F-TRD-09、F-OPE-01~03、F-VOC-04 |
| M6 | 社区扩展 | F-COM-01~07、F-ACC-04~05、F-SHOP-03 |
| M7 | 压测收尾 | 非功能需求验收 |

## 8. 验收标准

1. 每个迭代任务卡"验证记录"完整，接口可复现调用
2. M3 完成后：压测下不超卖、一人一单成立
3. M5 完成后：构造故障（杀服务/丢消息）后，对账任务能发现并补偿一致
4. M7 完成后：产出压测对比报告与架构文档
